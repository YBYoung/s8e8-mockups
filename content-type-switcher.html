Content Type Switcher

Let the team change whether a page is a Service page, Blog article, or Pillar page after it's been created. One control, same behavior, in three places: the hub table, the hub detail panel, and the editor toolbar. Everything below is clickable, try changing a few types.

How it works under the hood

The type is stored in two places: the calendar item (the plan) and the production piece (the draft). This control writes the piece, and offers to keep the calendar in sync.

What it writes

  • Updates the production piece's type immediately (new backend endpoint, none exists today).
  • "Also update the calendar item" is checked by default, so plan and draft stay matched.
  • If the calendar is mid client-review, the sync option is disabled with a note (calendar edits are locked during review).

Guardrails

  • Draft, not yet written: instant change, undo toast. No friction.
  • Content already generated: confirm dialog listing what shifts (word targets, required sections, QA rules).
  • Published to Webflow: extra red line in the dialog, since the live item would sit in the wrong collection until republished.

What a type change ripples into

  • QA rules: service pages require FAQ + CTA; blogs don't. Word floors differ (1,250 / 1,600 / 2,800).
  • Optimizer + writer: prompts, golden examples, and depth all key off type.
  • Webflow: type picks the CMS collection at publish time.
  • Asana: service pages sync to a different section with different phases.
