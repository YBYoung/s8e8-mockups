Section A

Tier accents on every row and the pane

Each row gets a thin edge accent plus a tier tag in the Asana-true colors from your screenshot: gray for Website Support, teal for Essential, green for Performance, yellow for MRKT Leader. The tag replaces the current muted tier text under the client name. Website Support finally reads as its own thing instead of masquerading as Essential.

Section B

Filters that can exclude, and Website Support is filterable

Every filter dimension gets an is / is not toggle. "Tier is not Website Support" hides support clients; "Tier is Website Support" shows only them. Exclude chips render red with a "not" prefix so an active exclusion is impossible to miss. Two new dimensions ride along: Data health gains "Broken" (connected but no recent data, Section C) and Website arrives with Section D.

The tier dropdown now lists four values: Essential, Performance, MRKT Leader, and Website Support. Today support clients fall back to "essential" and cannot be told apart; the backend already knows who they are (is_web_support), the filter just never used it.

Section C

Broken connections: see them, recheck them, reconnect without disconnecting

Today a dead Search Console connection still shows a green dot, and the only recovery is Disconnect → reconnect from scratch. Three changes: a third dot state (solid red = connected but broken, hollow red = never connected), the pane's Data section names the problem and offers Recheck and Reconnect directly, and the connect modal's connected cards get Test and Change so Disconnect stops being the only button.

Section D

Website status: Live, Starter only, or no Webflow site

A nightly check against Webflow classifies every client: Live (site published on its own domain), Starter only (a site exists but only on webflow.io — not launched, like Allen Family Dentistry), or No site (nothing in Webflow matched to this client). Starter and No-site clients show as Paused — not auditable yet instead of piling up as overdue. When a starter site graduates to a launched CMS site, the nightly check announces it (Section F).

That is the signal, plus whether the site has real CMS collections. Paused clients drop out of the overdue count and get their own Website filter value (Section B), so "215 days over" stops appearing on clients we were never going to audit.

Section E

Connecting queue: every backfill in one place

Today a backfill is only visible inside the connect modal of the one client you just connected, and only while it's open. This adds a Connecting lane next to Data health: every client currently backfilling, recently finished, or stalled — with per-source progress. Anyone on the team can see what's cooking without keeping it in their head.

Section F

Notifications: the hub tells you, you read it on your own time

A bell in the hub header (shown at the top of this page). The nightly checks write announcements; each person has their own read/unread state, so Jonna reading one does not clear it for you. First feed sources: site launches, backfills finishing or stalling, and connections going broken.

Under the hood

What each section needs, in plain terms

  • A · Tier accents — frontend only. The hub rows already carry tier and the support flag; this is styling. Ships fast once you pick stripe+tag or tag-only.
  • B · Exclude filters — frontend only. The filter system gains an is/is-not bit per dimension; saved filters carry it. The Website Support tier value uses the support flag the backend already sends.
  • C · Broken connections — the "no data for N days" signal already exists in the hub (it currently only powers a hover tooltip). New: a Recheck endpoint that live-tests one source against Google and remembers the permission level, and connectors that can re-pick without disconnecting first. Also fixes the bug you hit today: the right-side card will refresh itself after the connect modal closes (found the cause — it's a one-line-class fix territory, listed separately in chat).
  • D · Website status — a nightly job asks Webflow for the site list (one call for the whole agency), classifies each client (custom domain = live; webflow.io only = starter; nothing linked or matched = no site), and stores the result on the client. Needs two new columns on the clients table — that's a protected table, so this waits for your explicit go-ahead. "Paused" also changes what counts as overdue, which is a workflow rule change worth a sentence of your confirmation.
  • E · Connecting queue — needs a small backfill-status record the server writes as it works (started, per-source progress, finished/stalled). This is the "backfill failures are invisible" gap from the 7/31 audit; the queue lane is its face. Resume = restart from where the cache actually is, which the backfill already knows how to do.
  • F · Notifications — new small table (announcement + who read it), one endpoint pair (list, mark read), the bell. Fed by the Section C, D, E nightly checks. Greenfield but deliberately tiny.
