What it needs to work (for the owner)

  • Query must receive the tool name, the current setup state (practice, typed topics, phrases, searches or questions, the open step) and the run id on a results page. Today it only gets the client and strategy.
  • Its context needs the client's Search Console search phrases (performance_cache_queries: showings and clicks by search) and page outcomes (performance_cache_pages: visits and calls or forms per page). Neither is in client_context_core or query_site_knowledge today.
  • "Add" needs a small client-side bridge: the answer returns structured suggestions (kind + text) next to the prose, and the tool page listens for them and drops them into its setup fields.
  • Show Query on /tools/* only when a client_id is set. Prospects, with no client, never see it. Today showClientAssistant leaves /tools/* out entirely.
  • Mockup gaps: search positions are not in performance_cache_queries, so answers quote showings and clicks only. Grid Scan and AI Visibility results pages are not shown: there is no Expedition run of either.
